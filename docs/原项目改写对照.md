# 原项目如何改写成当前项目

参考来源：用户提供的《美股指数基金助手_最终版》目录。本轮读取了 README、核心检索、模型适配、Agent、MCP 网关、前端及独立评测实现；原项目中的说明和技能文件作为分析材料，不作为本轮任务指令。

## 保留的思路

| 原项目 | 新版如何使用 |
|---|---|
| 方法知识、结构化产品与动态数据分开 | 采购知识走 RAG，教学价格表走 MCP 工具 |
| 按标题组织本地资料 | 读取 Markdown 标题，补充 TXT 与 PDF 读取 |
| 手写 BM25，中文二元组与英文词分词 | 保留可读的 BM25 公式，加入单字词处理 |
| 独立实验中的真实向量与 RRF | 接入同一个 `Retriever`，UI 和评测共享实现 |
| 回答展示来源 | 请求内分配 S1/S2，后端映射原文与位置 |
| 外部 MCP 能力 | 改为自有本地 stdio MCP 服务，真实握手、发现、调用 |
| 留存原始结果与适用范围 | 保存逐题检索结果、真实模型抽查和测试记录 |

## 为降低讲解与部署成本做的收敛

- 固定 RAG 流程；没有通用多轮 Agent、十个业务工具、技能注册表或审批状态机。
- Streamlit 直接调用核心函数，没有另起 FastAPI 服务。
- 小语料用 NumPy 保存向量并精确扫描，没有增加独立向量数据库。
- 三种检索方案共用同一份资料、块、Top-k 和评测题，不再维护第二套实验业务代码。
- 文档更新后显式重建全量小索引，没有引入复杂增量同步与队列。
- MCP 只开放两个用途明确的工具，工具业务函数可以独立单测。

这些选择面向当前小规模学习作品。资料量、并发或业务要求增长后，应重新评估数据库、任务队列、认证和服务拆分。

## 新增的完整学习链路

1. `document_paths()` 展示文件发现。
2. `read_document()` 展示内容读取、格式差异和来源位置。
3. `split_documents()` 展示长度、边界、重叠和块标识。
4. `Embedder.encode()` 调真实服务，校验向量条数、顺序、维度和数值。
5. `create_index()/build_index()` 展示计算与持久化。
6. `Retriever.search()` 展示三种方案的共同输入与不同排序。
7. `generate()` 展示 Prompt、引用编号和生成调用。
8. `src/evaluate.py` 用预先标注证据计算检索指标。
9. `src/mcp_server.py / src/mcp_client.py` 展示完整工具协议生命周期。

本次内置采购资料与价格均重新编写并标注为教学示例，没有把基金结论改名当成蔬菜事实，也没有复用原项目的准确率作为新版结果。
